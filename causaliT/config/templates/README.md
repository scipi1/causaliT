# Configuration Templates

This directory contains standardized configuration templates for all CausaliT model architectures.

## Experiment Naming Convention

All experiments should follow a consistent naming convention to enable automated validation and easy identification of experiment configurations.

### Format

```
<architecture>_<SelfAttn>_<CrossAttn>_<dataset>_[modifiers]_<ID>
```

### Components

| Component | Required | Options |
|-----------|----------|---------|
| `architecture` | Yes | `single`, `na_single`, `stage` |
| `SelfAttn` | Yes | `SM`, `Lie`, `PhiSM`, `Toeplitz` |
| `CrossAttn` | Yes | `SM`, `CC`, `PhiSM` |
| `dataset` | Yes | `scm1`, `scm2`, `scm3`, `scm6`, `scm7`, etc. |
| `modifiers` | No | `SVFA`, `antisym`, `gated`, `indep`, `hard`, `orthS` |
| `ID` | Yes | Euler job ID or random hash |

### Architecture Mapping

| Abbreviation | Model Class |
|--------------|-------------|
| `single` | `SingleCausalLayer` |
| `na_single` | `NoiseAwareSingleCausalLayer` |
| `stage` | `StageCausaliT` |

### Attention Type Abbreviations

| Abbreviation | Self-Attention | Cross-Attention |
|--------------|----------------|-----------------|
| `SM` | `ScaledDotProduct` | `ScaledDotProduct` |
| `Lie` | `LieAttention` | - |
| `PhiSM` | `PhiSoftMax` | `PhiSoftMax` |
| `Toeplitz` | `ToeplitzLieAttention` | - |
| `CC` | - | `CausalCrossAttention` |

### Modifier Meanings

| Modifier | Config Setting | Notes |
|----------|----------------|-------|
| `SVFA` | `comps_embed_X: "svfa"` | Explicit for `single`/`stage`; **implicit for `na_single`** |
| `orthS` | Orthogonal frozen S embedding | Default is learnable S (no modifier needed) |
| `antisym` | `dag_parameterization_self: "antisymmetric"` | |
| `gated` | `dag_parameterization_self: "gated"` | |
| `indep` | `dag_parameterization_self: "independent"` | |
| `hard` | `training.use_hard_masks: true` | |

### Excluded from Naming Checks

The following experiment types use their own naming patterns and are excluded from automated validation:

- **ANS experiments** (`ANS_*`) - Attention Necessity Score analysis
- **Sweeps** (`sweep_*`) - Parameter sweep experiments
- **Sweep combinations** (`*combo*`) - Generated by sweeper

## Embedding Modes

### Standard Summation
Default for `config_single_causal.yaml` and `config_stage_causal.yaml`:
- Embeddings are summed: `E = E_value + E_variable + mask`
- All components share the same dimension

### SVFA (Structure-Value Factorized Attention)
Used in `config_single_causal_svfa.yaml` and `config_noise_aware.yaml`:
- Separates embeddings into structure and value components
- Structure: used for attention computation (Q, K)
- Value: used for output computation (V)
- Requires `role: "value"` and `role: "structure"` in module definitions

### Orthogonal Frozen (Alternative for S)
Commented in templates as an alternative for S embeddings:
- Fixed orthogonal vectors for each variable
- No learnable parameters (frozen)
- Useful for deterministic intervention variables
- Add `orthS` modifier to experiment name when using this

## S Embedding Options

All templates now support **learnable S embeddings** as the default, with **orthogonal frozen** as a documented alternative:

```yaml
# DEFAULT: Learnable S embedding (same structure as X)
ds_embed_S:
  setting:
    d_model: ${model.embed_dim.d_model_set}
    sparse_grad: false
  modules:
    - idx: ${data.feature_indices.value}
      embed: "linear"
      label: "value"
      # ... etc

comps_embed_S: "summation"  # or "svfa" for SVFA templates

# ALTERNATIVE: Orthogonal frozen (commented in templates)
# Use orthS modifier in experiment name when enabling this
# ds_embed_S:
#   num_variables: ${data.S_seq_len}
#   value_input_dim: 1
#   value_idx: ${data.feature_indices.value}
#   var_idx: ${data.feature_indices.variable}
#   freeze: true
```

## Auto-populated Fields

The following fields are automatically populated from `dataset_metadata.json`:

```yaml
data:
  S_seq_len: null        # Source sequence length
  X_seq_len: null        # Input sequence length
  Y_seq_len: null        # Target sequence length
  num_embeddings_S: null # n_source + 1
  num_embeddings_X: null # n_input + 1
  num_embeddings_Y: null # n_target + 1
  num_embeddings_shared: null  # Total unique + 1
  
  feature_indices:
    value: null          # Column index for values
    variable: null       # Column index for variable IDs
```

## Usage

1. **Copy template to experiment folder:**
   ```bash
   # For single architecture
   mkdir -p experiments/single/scm6/single_Lie_SM_scm6/
   cp causaliT/config/templates/config_single_causal.yaml \
      experiments/single/scm6/single_Lie_SM_scm6/config.yaml
   
   # For noise-aware architecture
   mkdir -p experiments/noise_aware_single/scm1/na_single_Toeplitz_SM_scm1/
   cp causaliT/config/templates/config_noise_aware.yaml \
      experiments/noise_aware_single/scm1/na_single_Toeplitz_SM_scm1/config.yaml
   ```

2. **Modify dataset and hyperparameters:**
   ```yaml
   data:
     dataset: "scm6"
   
   experiment:
     d_model_set: 24
     dec_self_attention_type: "LieAttention"
     max_epochs: 200
   ```

3. **Run training:**
   ```bash
   python -m causaliT.cli train experiments/single/scm6/single_Lie_SM_scm6/
   ```

4. **Validate naming consistency:**
   ```bash
   # Run the naming consistency test
   python tests/test_naming_consistency.py
   
   # Or via pytest
   pytest tests/test_naming_consistency.py -v
   ```

## Standardization Notes

All templates follow these conventions:

1. **Feature indices**: Use `data.feature_indices.value/variable` (not `data.features.shared`)
2. **Regularization defaults**: All regularization parameters default to `0.0`
3. **Logging flags**: All logging flags are explicitly listed
4. **Evaluation section**: All templates include an `evaluation.functions` list
5. **Comments**: Major sections are clearly delimited with `=========` headers
6. **Naming instructions**: Each template includes a header explaining the naming convention
